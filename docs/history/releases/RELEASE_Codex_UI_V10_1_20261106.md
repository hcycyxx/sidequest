# SideQuest UI V10.1 · 高刷新率优化

Jack 确认 V10 真实界面显示正常，要求停止测试，并指出当前屏幕为 165Hz、动画帧率偏低。

## 改动

- 动画调度从固定 `1/60` 改为目标 `1/165`，扣除上一帧处理时间后再等待，减少累计延迟。
- 动画期间临时使用 1ms 计时精度；停下来和退出时释放。闲置循环降至 25Hz。
- 原有弹簧曲线、阻尼速度、任务界面和功能保持原样。
- 缓存窗口句柄，用一次本机调用同步位置和尺寸，减少 Python/.NET 往返。
- 圆角区域只在实际尺寸变化时更新；单纯移动不重建。
- 高频 fit/hold/hover 请求不再触发整套 JavaScript 界面重绘；拖动中不重复回传整套界面，结束时同步位置。
- 原始 V10 源文件、启动器和版本包全部保留。新入口为 `sidequest_v10_1.py`。

## 启动

```powershell
.\launch_sidequest_v10_1.ps1 -ReplacePanel
```

替换只关闭本项目面板，不重启采样进程或模型引擎，不改任务记录和暂停状态。
回退时用原 `launch_sidequest_v10.ps1`，运行前先关闭新版面板。

## 验收边界

依 Jack 要求，本版没有运行测试、截图检查或帧率测量。
165Hz 是动画更新的调度目标，不等于已测得 165FPS；实际效果受 Windows 合成、显示缩放和渲染组件影响。
由 Jack 直接体验展开收起、拖动缩放及贴边滑动的顺滑度。
