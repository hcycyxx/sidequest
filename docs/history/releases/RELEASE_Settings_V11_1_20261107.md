# SideQuest V11.1 · 设置页修复与模型连接按钮

## 修复原因

旧设置页将输入框创建在外层容器中，却只把标签放进行容器，输入框没有进入对应行；
多个独立 pack 布局争抢空间，导致标签与输入框分离、空白过大、下方设置不可见。

## 新设置页

- 统一为“模型连接 / 监测与内容 / 界面与日报”三页签。
- 标签、输入框、说明均在各自正确的父容器中，以两列网格对齐。
- 页面可滚动，保存和关闭固定在底部；说明按实际可用宽度换行。
- 模型名称支持下拉选择，也允许手动填写。
- API Key 默认隐藏，可点击显示；不在请求错误或日志中回显密钥。
- 字号、分析间隔和日报时间验证后再保存，不再静默将非法值改成默认数值。
- 修正只保存API设置时，未修改的旧字号可能覆盖面板新字号的问题。

## 新增按钮

- **获取模型**：使用界面当前填写的地址与密钥请求 `GET /models`，填充模型下拉列表。
- **检测连通性**：检查同一模型列表端点的HTTP/认证/响应结果，明确标明没有调用模型推理。
- 请求在后台线程执行，超时8秒；结果经队列回到Tk主线程更新，不阻塞界面。
- 401/403/404/429、超时及非兼容响应分别提示。404明确不能据此认定聊天接口不可用。
- 只有用户按下按钮才发请求。保存设置、打开窗口和本轮打包均不执行连通性请求。

原模块保留为 `ui/settings_window_legacy_v11.py`，当前兼容入口转到 `settings_dialog_v11_1.py`。
原数据桥保留为 `ui/bridge_core_v11_0.py`，其他主界面、计时、识别与保存规则不变。
