# SideQuest V11 · 全部优化接入

Jack 已授权本轮全部优化，并要求不运行测试。界面风格、卡片、长按拖动、烟花、阻尼、
165Hz调度目标和2秒窗口停留统计沿用V10.9。

## 1. 进程身份与启停

`engine/process_control_v11.py` 一次查询相关Python进程，核对实际入口脚本、解释器路径及创建时间。
终止时再次从同一个进程句柄读取路径和创建时间；不匹配则拒绝操作，不按旧PID文件盲杀。
启动前检查已运行的真实后台，不因PID记录丢失便重复启动。
项目命名互斥锁串行化跨进程启停。识别不明确或扫描失败时不盲目强制启动/停止。

## 2. 窗口响应与后台解耦

- 后台启停由独立生命周期队列执行，不占用窗口几何锁。
- 任务数据锁和窗口控制锁分开；窗口操作需要保存偏好时，先离开几何锁再进行文件操作。
- 保留退出标志与排队顺序，退出时拒绝后续恢复，避免后台在关窗后重新启动。
- 日报检查及托盘历史读取移至维护线程，动画循环不直接执行周期文件扫描。
- 关闭窗口期间显示正在退出，待已核验后台停止后再销毁窗口；失败显示状态，避免假装全部退出。

## 3. 时间轴

- 使用同一SQLite库及原记录，增加索引、WAL和按记录ID覆盖的变化通知，不删除历史。
- 历史采用游标分页，默认100条；打开后每2秒只读取变化记录。
- 前端按ID保留已有节点，只改时间、时长和条形宽度；不再每2秒销毁重建整批列表。
- 继续按前台窗口停留累计，不扣键鼠空闲；暂停、锁屏及休眠中断仍不外推。

## 4. 请求等待与结果核对

- 一般请求8秒等待提示；任务保存/撤销超过12秒显示结果待核对，不自动重发。
- 界面提供“核对保存结果”。已完成的请求返回轻量回执和新视图；未开始的请求会在同一数据锁中登记取消，阻止迟到写入。
- 写入完成后先保存回执，再刷新界面；刷新失败不再误称任务未保存。
- 去重缓存保存轻量回执，不反复缓存整份任务列表。
- 延迟核对后的成功不在旧鼠标坐标播放庆祝，避免与当前操作混淆。

## 5. 固定最新版入口

日常只用：

```powershell
.\launch_sidequest_latest.ps1
```

只替换界面、保留现有后台和暂停状态：

```powershell
.\launch_sidequest_latest.ps1 -ReplacePanel
```

对应稳定脚本为 `sidequest_latest.py`，当前版本由 `ui/current_release.json` 指定。
原 `sidequest.py` 和 `engine/ctl.py` 改为兼容转接，不再默认打开旧界面。
其原始源码分别保留为 `sidequest_legacy_v9.py`、`engine/ctl_legacy_v9.py`；历史版本包不覆盖。
显式回退前先关闭当前界面，再使用旧版本入口；不要把历史启动器当日常最新版入口。

## 6. 公共模块

- `ui/app_v11.py`：统一桌面初始化。
- `ui/desktop_core.py`：单一窗口控制类，不再导入历史窗口类链。
- `ui/bridge_core.py`：单一数据桥，复用原state_store保存规则及详细设置/日报组件。
- `ui/timeline_core.py`：窗口停留、事件存档、分页和变化通知。
- `ui/web_core/`：按请求、任务、动画、拖动、窗口、时间轴、初始化拆分源码；启动时本地连接在一个局部作用域中。
- 本轮不引入构建工具或额外桌面依赖，仍用已安装的本地WebView2运行环境。

## 后台健康状态

主标题显示核验、切换、暂停、异常或运行状态；外观与设置中新增“后台状态”详情。
显示窗口监测/任务识别是否运行、最近成功识别时间、识别错误类别和进程核验问题。
未切换的既有引擎通过已有日志提供时间，并明确标为日志记录；以后正常启动的
`engine/llm_engine_v11.py` 会在原推理流程中写入明确成功/失败状态，不增加模型验证调用。

## 数据和范围

任务JSON、人工状态优先级、模型提示词及任务识别规则未改变。原偏好与拖动顺序保留。
SQLite只增加索引与元数据触发器；旧表及历史内容保留。近期新写入可能位于SQLite的WAL文件中，
需要复制数据库时应先退出程序或使用SQLite在线备份，不能只在运行中复制主库文件。
本次切换只替换面板，不为了验证而重启后台或调用模型。
