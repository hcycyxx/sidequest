# V9：原生揭示过渡、减少模型提交与闲置自动休息

## 动画

V8 已降低文字层复制开销，但仍每帧修改 Windows 窗口尺寸。本版在同宽展开/收起时一次准备完整窗口，再用 Windows 原生圆角区域逐帧揭示内容；任务列表视口保持稳定，文字层同步裁剪。
缓动采用起止速度/加速度都归零的平滑曲线，展开约300ms、收起约240ms，不用强弹跳。动画期间临时提高计时精度，结束或中断后释放；原生区域不可用时回退到原有尺寸过渡。

独立、已映射 Tk 窗口测试：一次展开仅提交1次原生尺寸变更，区域路径成功启用且结束后清除。覆盖重复/反向开合、透明切换、四皮肤、稳定图形复用；无Tk回调错误。此检查不等于真实桌面每帧视频验收，最终手感仍由 Jack 在新版中确认。

## 模型请求

- 原来每轮用户消息以当前秒级时间开头。现在固定系统规则，成功轮次的输入/输出原样保留，下一轮只在尾部追加当前权威状态与新活动；时间放在新增消息尾部。
- 上下文最多保留6轮，或历史超过24000字符后用当前状态重新建立，防止无限增长。
- 比较活动与任务的语义签名，忽略纯采样时间、停留秒数等噪声。同一内容不再每分钟提交；有实质变化按原间隔分析，静态但仍有人使用时最多每5分钟低频复核。
- 用户手动勾选等权威状态改变仍触发分析。失败有退避，失败响应不追加进成功上下文。
- 新增 config/llm_usage.jsonl：仅记录模型名、时间、输入/输出及缓存token数。不记录密钥、请求正文或截图。支持 DeepSeek usage.prompt_cache_hit_tokens 与通用 prompt_tokens_details.cached_tokens；代理不返回时明确未知，不把缺字段当命中0。

参考 https://api-docs.deepseek.com/guides/kv_cache/ ：相同前缀可复用缓存，但缓存是尽力而为，且真实接口为本地 WorkBuddy 代理，其缓存语义和费用不能直接套用官方 DeepSeek。未通过额外模型调用测试缓存率，后续由正常生产请求返回的用量统计验证。

## 30分钟自动休息

采样进程继续每2秒轻量检查。键鼠无输入且前台窗口画面无明显变化均累计30分钟后，模型提交暂停。窗口标题变化、键鼠操作或明显画面变化会唤醒；引擎每5秒检查休息状态，唤醒后给内容采样留出5秒再分析。

画面判断在人无输入2分钟后每15秒取一次前台客户区小样本（48×27灰度），忽略光标等微小闪动；只在内存中比较，屏幕图像不落盘。config/activity_status.json 只存检查时间、闲置秒数、休息标志和活动计数。界面标题显示“自动休息”。

首次启动需要实际累计画面静止时间，不回填未观测的半小时。若内容抓取关闭或截图组件不可用，则回退到键鼠与窗口变化检测，不能保证检测所有同窗口画面变化。手动暂停仍优先，手动暂停不会因键鼠操作而自行启动后台。
