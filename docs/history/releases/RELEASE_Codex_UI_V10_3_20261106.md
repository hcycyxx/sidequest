# SideQuest UI V10.3 · 代码检查与修复

按 Jack 要求，只进行静态源码检查和修复，没有运行测试、浏览器、截图或模型验证。
本版建立在 V10.2 上；旧源文件、启动入口和版本包全部保留。

## 本次修复

1. 任务保存、撤销、暂停或设置修改前开始的旧刷新结果，现在会被丢弃，避免覆盖新操作的界面状态。
2. 设置保存按顺序提交，保存期间暂停轮询，避免快速换肤/改字号/开合造成先后顺序倒置。
3. 主任务标题加入步骤控件重建条件，任务被 AI 改名后不再继续发送旧标题。
4. 撤销独立管理保存锁及完成清理；无关按钮报错不再清掉正在保存的任务状态。
5. 没有主线或保存中时，禁用的完成按钮不再显示绿色成功样式。
6. 上一次拖动结束未提交完成时，不建立第二次手势；重复结束事件被忽略。
7. 启动前统一校验两份偏好的数值、布尔值、皮肤和坐标；非法值在内存中回退默认值，不改写原文件。
8. 任务结构异常时保留上次有效内容；人工状态格式异常时拒绝写入并说明原因。
9. 暂停/恢复和退出使用同一把锁；应用关闭后拒绝恢复请求，防止退出后后台被再次启动。
10. 拖动、停靠或重置的偏好保存失败会向上返回错误，不再误报已成功。

本轮两份独立静态检查分别覆盖前端异步状态和 Python 数据/窗口控制。
没有宣称完成动态验收或已经排除所有 Bug。由 Jack 按日常使用直接反馈。

## 接入

入口：`sidequest_v10_3.py`。
切换：`launch_sidequest_v10_3.ps1 -ReplacePanel`。
仍使用既有本地运行环境，只替换界面进程，不重启后台或批量改变真实任务。
165Hz 调度、V10.2 外框高度同步和已确认界面继续沿用。

## 功能建议，尚未实施

优先建议：

- **指定今日主线**：可把某项现有任务选为当前主线，避免所有工作都落在支线、主区显示暂无任务。
- **手动修正任务**：新增、改名及合并重复任务；需要明确人工字段优先级，防止下一轮 AI 又改回。
- **任务搜索与筛选**：任务较多时按进行中、等待回复、待确认、已完成查找。

后续可选：明确显示最近一次成功识别时间及失败原因；为等待回复或到期任务提供用户选择时间的提醒。
本轮未加新按钮、未创建提醒、未自动选择跟进间隔。

架构方面：目前多版本入口和继承链逐渐增加。建议使用稳定后再合并公共启动/窗口代码，
保留版本归档；本轮先限定为小范围错误修复，避免在不运行测试的情况下进行大重构。
