# SideQuest V7 · 五项优化交接

## 启用

源码已在原路径更新。没有重启正在运行的 UI/采样/AI，没有调用模型接口，也没有修改真实任务 JSON。
请由 Jack/DSH 按原流程整体重启源码版后生效。现有 dist 安装包/EXE 没有重新打包；若使用 EXE，需重新构建后再切换。
UI、engine 更新应一起使用，包含新增的 `engine/task_policy.py`，不增加第三方依赖。

## 行为

1. **完成更保守**：删除“两小时未碰即完成”的规则。AI 输出新的 done 会被本地规则转为 pending＋completion_candidate，显示“待确认”；用户确认才进入完成历史。原来已经完成的历史不会因此被重开，用户手动状态继续优先。模型发现自己过去误判仍可按原机制申请 reopen。
2. **来源可追溯**：窗口可见文字优先；磁盘候选作为兜底。候选路径、文件修改时间、抓取时间和范围写入采样记录，并随提供给模型的内容传递。遇到多个同名文件拒绝猜测；标题带 * 时跳过磁盘内容。磁盘候选仍可能不是当前工作表或未保存视图，提示词明确要求交叉核对，不能宣称已准确绑定活动文件。
3. **短进展和估算区间**：要求任务级 live_progress（最多22字）、progress_range（0–95）、progress_basis。缺依据/非法区间被去掉；等待状态沿用已有估算。UI 显示“估算30–50%”并在说明中给依据，仍保留“步骤2/4”的独立来源含义。无法估算时保持待估算；待确认完成不显示伪100%。这不等于已经验证 AI 实际估算准确率。
4. **默认列表更短**：主线默认1项，支线3项，其余由“查看其余N项”展开。已完成入口改为独立历史窗口，可选择并恢复任务。四套皮肤、暂停、透明叠层、托盘、滚动、完成动效继续复用。
5. **日报新版本保存**：新文件格式 YYYY-MM-DD_HHMMSS_微秒_随机尾缀.html，独占新建，保留原有日期.html。history 按日显示最新版本，versions(day) 可取得全部版本。首次打开无日报时，等待后台生成成功再打开；任务忙碌时的打开请求会被保留；只有生成成功才写自动完成标记，失败五分钟后可自动重试，也可手动重试。
